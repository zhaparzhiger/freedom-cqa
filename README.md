# Freedom CQA — оценка качества диалогов операторов

Веб-прототип Conversation Quality Analytics для хакатона Freedom Broker. Система оценивает работу оператора в чате или звонке по настраиваемому чек-листу, объясняет каждую оценку со ссылкой на реплику, принимает апелляции и решения проверяющего, учится на этих решениях и сама готовит тренировки для операторов.

## Запуск

Нужен Node.js 20+ (проверено на 24).

```bash
npm install
cp .env.example .env      # заполнить доступ к Gemini и ссылку на API организаторов
npm start                 # http://localhost:8870
```

В `.env`:

| Переменная | Что это |
|---|---|
| `GOOGLE_APPLICATION_CREDENTIALS` | путь к JSON-ключу сервисного аккаунта Google Cloud (Vertex AI) |
| `GEMINI_API_KEY` | либо ключ Google AI Studio, если сервисного аккаунта нет |
| `GEMINI_MODEL` | основная модель, по умолчанию `gemini-3.5-flash-lite` |
| `GEMINI_FALLBACK_MODELS` | запасные модели при перегрузке (HTTP 429), по умолчанию `gemini-3.1-flash-lite` |
| `EVAL_MODE` | `agents` — мультиагентный конвейер (по умолчанию), `single` — один вызов |
| `ORG_API_URL` | GET-ссылка из Student Guide (кнопка «Открыть GET для DEV»); `group_id` подставляется сам |
| `PRICE_INPUT_PER_M`, `PRICE_OUTPUT_PER_M` | цена модели за 1 млн токенов — для расчёта стоимости оценки |

Регистрация и вход не нужны. Роль «Сотрудник / Проверяющий» переключается в шапке.

## Сдача результатов (формат JSON 1.0 из приложения к гайду)

- `results/dev/results.json` — DEV, 65 диалогов: `node scripts/results.js --group DEV --out results/dev/results.json --expect 65`
- `results/prod/results.json` — контрольный набор, одной командой при запущенном сервере:

```bash
node scripts/control.js --group <group_id> --push        # или --url "<ссылка>" / --file prod.json
```

Команда загружает набор, оценивает его мультиагентным конвейером, один раз повторяет упавшие диалоги, выгружает `results/prod/results.json`, проверяет формат (8 критериев, ровно 10 записей, ошибки — со `status: "error"`) и делает commit и push. В выгрузку идут ответы ИИ; номера реплик в `evidence_turns` и в тексте объяснений — с 1, как требует приложение. Та же выгрузка доступна кнопкой «results.json для сдачи» в списке диалогов.

## Как пройти контрольный этап

1. **Диалоги → Набор из API организаторов** — ввести выданный `group_id`, нажать «Загрузить набор».
2. Выбрать режим «Мультиагентный конвейер» и нажать «Оценить все неоценённые». Прогресс и стоимость видны сразу.
3. **Экспорт CSV / JSON** — итоговые оценки по всем диалогам.
4. Замена критерия: **Чек-листы** → изменить или добавить критерий → «Оценить влияние» (видно, сколько диалогов затронет и как сдвинется средний балл) → «Сохранить и применить». Пересчитывается только изменённый критерий, остальные берутся из прошлых оценок.

## Что умеет

**Оценка (контур 1)**
- Чек-лист настраивается в интерфейсе: критерии, разделы, вес, тип ответа (Да/Нет, шкала, флаг без баллов), доступность N/A и её условие, ступени шкалы, уточнение для ИИ, общие правила. Каждое сохранение — новая версия; оценка хранит снимок чек-листа, по которому сделана.
- Транскрипт загружается из API организаторов или JSON-файлом. Поддерживаются RU, KZ, EN; реплики бота и системные события — контекст, оценивается только оператор.
- По каждому критерию: ответ, баллы, вес (и вес после перераспределения N/A), объяснение, реплики-доказательства (клик — переход к сообщению, у звонков — перемотка записи), для пропущенного действия — проверенный участок, для N/A — выполненное условие. Итог, разделы, отдельная отметка грубой ошибки.
- **Баллы считает код, а не модель** (`public/js/scoring.js`, покрыт тестами): «Да» — полный вес, шкала — пропорционально, веса N/A перераспределяются, итог из 100 с округлением до двух знаков.

**Работа с результатом (контур 2)**
- Карточка диалога: транскрипт рядом с результатом, плеер записи звонка со скоростью воспроизведения.
- Апелляция по критерию с комментарием и ожидаемой оценкой; очередь апелляций; решение проверяющего (подтвердить или изменить с причиной) с пересчётом итога. В карточке видны исходная оценка ИИ, решение и финальный результат.

**Сверх задания**
- **Мультиагентный конвейер**: агент контекста строит «карту диалога» → отдельный агент на каждый критерий (параллельно, видит только своё правило — одно нарушение не наказывает дважды) → валидатор правил в коде → агент-проверяющий ищет противоречия → агент-уточнитель пересматривает спорное. Весь ход проверки виден в карточке.
- **Проверка доказательств**: код сверяет, что реплика существует, что положительный вывод о работе оператора опирается на реплику оператора, что нарушение подтверждено репликой оператора. Иначе — метка «⚠ Требует проверки человеком».
- **Превью влияния изменения чек-листа**: до сохранения — сколько диалогов затронет, средний балл «было → стало», хуже/лучше. Изменение веса — без ИИ мгновенно; изменение текста — пересчёт только этого критерия.
- **Проверяющий учит систему**: решения по апелляциям становятся прецедентами в промпте (кроме прецедентов того же диалога), кривая согласия ИИ с проверяющим и проверка «усвоил ли ИИ исправления».
- **Тест языковой честности**: русские диалоги переводятся на казахский и английский реплика в реплику и оцениваются заново; сдвиг балла сравнивается с шумом модели на повторной оценке того же русского диалога.
- **Тренажёр оператора** по ссылке без входа: разбор ошибок, ролевая игра с ИИ-клиентом по тому же сценарию (чат или голосом через Gemini Live), подсказки ИИ-коуча по ходу и итог «было → стало».
- **ИИ-ассистент «Аудитор»** — текстом или голосом в реальном времени (Gemini Live): отвечает по данным платформы (лучшие и худшие операторы, частые ошибки, грубые нарушения) и сам ведёт по интерфейсу — аватар подходит к строке, критерию или реплике и подсвечивает их. Аватар «дышит» в такт речи.
- **Аналитика**: средний балл, проблемные критерии, баллы по языкам, согласие с проверяющим, стоимость одной оценки.

## Модель и стоимость

Gemini через Vertex AI, по умолчанию `gemini-3.5-flash-lite`, при перегрузке — `gemini-3.1-flash-lite`. Одна оценка в режиме конвейера — около 10 вызовов модели, ~27 тыс. токенов, **≈ $0,006–0,01 за диалог** (по ценам из `.env`; сверьте с прайсом Google). Режим «один вызов» — около $0,003. Стоимость каждой оценки видна в карточке и в аналитике.

Точность проверялась на ручной разметке всех 65 диалогов DEV по тексту чек-листа (`data/labels/dev-*-reference.json`, это не эталон организаторов), конвейер на `gemini-3.5-flash-lite`:

| Набор | Совпадение ответов по критериям |
|---|---|
| Русские чаты (30) | 92,5% |
| Казахские чаты (15) | 91,7% |
| Английские чаты (15) | 93,3% |
| **Все чаты (60)** | **92,5%** |
| Звонки (5, расшифровка речи с ошибками) | 70% |

```bash
node scripts/eval.js --mode agents --ids p1-ru-001,p1-ru-002 --out data/runs/x.json   # пакетная оценка в файл
node scripts/accuracy.js --labels data/labels/dev-en-reference.json --verbose         # ru / kz / en / calls
npm test                                                                                 # тесты подсчёта баллов
```

`scripts/eval.js` без `--out` пишет в базу приложения — запускайте его при остановленном сервере.

## Встраивание в Dynamics 365

Интерфейс — чистые HTML, CSS и JavaScript без сборки. Адрес сервера задаётся через `window.CQA_CONFIG = { apiBase: '…' }`, сервер отдаёт CORS-заголовки. Карточку оценки можно встроить в любую страницу (HTML-веб-ресурс Dynamics 365) одной строкой — веб-компонент со стилями в Shadow DOM:

```html
<script type="module" src="https://<сервер-cqa>/embed/cqa-card.js"></script>
<cqa-card conversation-id="p1-ru-001"></cqa-card>
```

Пример страницы: `/embed/demo.html`. Компонент отдаёт событие `cqa-loaded` с баллом и флагом грубой ошибки.

## Устройство

```
server/
  index.js          HTTP-сервер, REST API, статика
  evaluate.js       оценка диалога: режим «один вызов» с голосованием, общий результат
  pipeline.js       мультиагентный конвейер и валидатор доказательств
  incremental.js    частичный пересчёт и превью влияния изменений чек-листа
  prompt.js         промпт и JSON-схема строятся из конфигурации чек-листа
  precedents.js     прецеденты из решений по апелляциям
  parity.js         тест языковой честности
  training.js       тренажёр: сценарий, ИИ-клиент, коуч, итоговая оценка
  live.js           голосовая тренировка через Gemini Live (WebSocket)
  assistant.js      ИИ-ассистент «Аудитор» с инструментами (текст)
  assistant-live.js голосовой режим ассистента через Gemini Live
  gemini.js         клиент Vertex AI / AI Studio: лимит параллельности, повторы, запасные модели
  store.js          хранилище — один JSON-файл data/db.json
public/
  index.html, js/   интерфейс администратора (без фреймворков)
  train.html        страница тренажёра для оператора
  embed/            веб-компонент <cqa-card> и пример встраивания
  js/scoring.js     подсчёт баллов (общий для сервера и браузера)
```

Хранилище — файл `data/db.json` (создаётся при первом запуске, в Git не попадает). Удалите его, чтобы начать с чистого листа.
